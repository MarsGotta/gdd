# CLI reference

Most of these commands are run for you by your agents through the
[gdd skills](../skills/index.md); you type few of them: `gdd init` once,
`gdd bootstrap` right after it, then `gdd board` to see your changes and `gdd sitting`
when a change waits for you. Now and then you also run `gdd status`, `gdd inbox`,
`gdd report`, `gdd changelog` and `gdd release`. Each command has a page with its
options, who runs it and real examples.

> [!NOTE]
> Generated by `scripts/make_reference.py` from gdd 0.1.0: the options come from
> `gdd <command> --help`, the rest of each page from `scripts/cli_notes/`. Do not edit
> these pages: change the help text in the code or the note, then run the script.

## Set up a project

| Command | What it does | Who runs it |
|---|---|---|
| [`gdd init`](init.md) | Sets up GDD in a folder: the harness, the Brief, the agents' skills, a stack skeleton. | You |
| [`gdd bootstrap`](bootstrap.md) | Runs the first install of each stack and commits its lock file. | You, your agents |
| [`gdd adopt`](adopt.md) | Records the checks a project with code already fails as known debt. | You, your agents |
| [`gdd agents`](agents.md) | Writes and checks the GDD skills in the folder of each coding agent. | You |
| [`gdd agents install`](agents-install.md) | Writes the GDD skills and the stack instructions for each agent. | You |
| [`gdd agents check`](agents-check.md) | Checks that each agent's GDD skills are exactly what gdd writes. | You |
| [`gdd stacks`](stacks.md) | Lists the stack sheets gdd comes with. | You |
| [`gdd stacks show`](stacks-show.md) | Shows one stack sheet: its tools, commands and protected paths. | You |
| [`gdd stacks compose`](stacks-compose.md) | Prints what several stack sheets give together, as TOML. | You |
| [`gdd upgrade`](upgrade.md) | Proposes the files a newer gdd writes, on a branch gdd-upgrade. | You |

## Plan and approve

| Command | What it does | Who runs it |
|---|---|---|
| [`gdd new-change`](new-change.md) | Creates a change: its record and its branch change/<id>. | Your agents |
| [`gdd classify`](classify.md) | Prints the color, lane and gates of a change, as JSON. | Your agents |
| [`gdd sitting`](sitting.md) | Opens the sitting of a change: approve it before Build, or answer its G4. | You |
| [`gdd gate`](gate.md) | Records a gate decision: G0, the red zones, the plan, or G1 to G4 of a change. | Your agents |
| [`gdd note`](note.md) | Leaves a note on a change for its Decision Inbox. | Your agents |
| [`gdd changelog-line`](changelog-line.md) | Sets the changelog line a change's merge commit carries. | You |

## Build and release

| Command | What it does | Who runs it |
|---|---|---|
| [`gdd launch`](launch.md) | Runs the recipe of a change: Build, G2, G3, the Reviewer, merge and pre. | Your agents |
| [`gdd resume`](resume.md) | Answers the G4 of a paused change: ok, ko or polish. | You, your agents |
| [`gdd park`](park.md) | Stops a change with a message for you in its Decision Inbox. | You, your agents |
| [`gdd prepare`](prepare.md) | Checks that a change may enter Build, and starts it. | Your agents |
| [`gdd merge`](merge.md) | Merges a change whose G3 is open into main, then deploys it to pre. | Your agents |
| [`gdd release`](release.md) | Runs a release step (pre, promote, observe), or releases the next version. | You, your agents |
| [`gdd changelog`](changelog.md) | Shows what CHANGELOG.md lacks and, with --write, adds it. | You, CI |

|---|---|---|
| [`gdd g2`](g2.md) | Loop Gate: the G2 commands, Path Guard and the scope, as JSON. | Your agents, CI |
| [`gdd g3`](g3.md) | Merge Gate: the G3 commands, Path Guard and the scenario count, as JSON. | Your agents, CI |
| [`gdd guard`](guard.md) | Path Guard: what a change touched that a role must not touch, as JSON. | Your agents |
| [`gdd snapshot`](snapshot.md) | Records what a change touched, so Path Guard judges only what comes after. | Your agents |
| [`gdd scope`](scope.md) | Lists what a change touched outside its plan, and what is accepted, as JSON. | Your agents |
| [`gdd selftest`](selftest.md) | Harness self-test: shows that the gates can say no. | You, your agents |
| [`gdd ci`](ci.md) | What CI runs: the harness unchanged, and G2 and G3 green, on the change's branch. | CI |

## Global behavior

### Options

| Option | What it does |
|---|---|
| `-h`, `--help` | Prints the help of `gdd` or of a command (`gdd gate --help`). Every command takes it. |
| `-V`, `--version` | Prints the version of gdd: `gdd --version`. Only `gdd` itself takes it. |

`gdd` with no command opens the [Board](board.md) when a person runs it in a terminal;
without a terminal, or for an agent gdd started, it prints its help. There are no other
global options: each command takes its own, after its name.

### Where it runs

Every command but `gdd init` runs in a project: the nearest folder, from the current one
upwards, that has `gdd/project.toml`. Outside one, it stops:

```text
error: not a GDD project: no gdd/project.toml in /home/me or the folders above it
```

`gdd init` is the other way round: it refuses inside a project. A command that works on
a change takes the change's id; where its usage shows `[CHANGE]`, the id may come from
`GDD_CHANGE` instead (see [Environment variables](../environment.md)).

### Output

Commands print text for people, except these, which print JSON on the standard output
for agents and scripts: [`gdd agents install`](agents-install.md),
[`gdd new-change`](new-change.md), [`gdd classify`](classify.md), [`gdd prepare`](prepare.md),
[`gdd merge`](merge.md), [`gdd release`](release.md), [`gdd g2`](g2.md), [`gdd g3`](g3.md),
[`gdd guard`](guard.md), [`gdd scope`](scope.md). `gdd report` prints JSON with `--json`.

An error goes to the standard error, on a line that starts with `error:`, and is never
JSON. A gate that says no is not an error: `gdd g2`, `gdd g3` and `gdd guard` print
`"ok": false` and exit with 0, unless you give them `--strict`.

### Exit codes

| Code | Meaning |
|---|---|
| 0 | The command did its job. A JSON verdict can still say `"ok": false`. |
| 1 | An error, a wrong command or option, or a check that failed: `gdd selftest`, `gdd ci`, `gdd agents check`, `gdd changelog --check`, a gate with `--strict`. `gdd park` always exits with 1, and so does a `gdd launch` whose change parks. |
| 2 | A screen without a terminal: `gdd board`, `gdd sitting`, or `gdd init` without its flags. |

### What agents cannot run

gdd knows a Builder or a Reviewer by `GDD_ROLE`, which `gdd launch` sets for every
agent it starts. These commands refuse them, whatever the agent tries:
[`gdd upgrade`](upgrade.md), [`gdd gate`](gate.md), [`gdd changelog-line`](changelog-line.md),
[`gdd resume`](resume.md), [`gdd release`](release.md), and
also `gdd selftest` and `gdd learn`. They stop with a message like this one:

```text
error: A Builder or Reviewer cannot open or close gates.
```

### Screens

Three commands open a screen, and only in a terminal: `gdd init` without `--name`,
`--platform` and `--stack` opens the Setup form, `gdd board` the Board, and
`gdd sitting` the sitting of a change. `gdd changelog` and `gdd release` without a step
ask before they write when they run in a terminal. Without a terminal a screen does
nothing, says what to use instead and exits with 2:

```text
error: gdd board needs a terminal; gdd status lists the same changes
```
