Loop Gate: the G2 commands of gdd/commands.toml, Path Guard and, in build mode, the scope.
Saves the result next to the change, logs it unless an agent runs it (GDD_ROLE) and prints it
as JSON.

## Uso

```text
Usage: gdd g2 [OPTIONS] [CHANGE]
```

## Argumentos

| Argumento | Descripción |
|---|---|
| `[CHANGE]` | Id of the change (its record is .gdd/changes/<id>/change.json); else GDD_CHANGE. |

## Opciones

| Opción | Descripción |
|---|---|
| `--role <ROLE>` | Role Path Guard judges (builder-build also gets the scope check). Por defecto: `builder`. |
| `--strict` | Exit with code 1 when the gate fails. |

## Quién lo ejecuta

Your agent, as the Builder, after each round in the
[`gdd-build-test`](../skills/agent-skills.md) skill (`--role builder-test`) and the
[`gdd-build`](../skills/agent-skills.md) skill (`--role builder-build`). [`gdd launch`](launch.md)
also runs it, and CI runs it through [`gdd ci`](ci.md).

## Ejemplos

Without `--strict` it exits with 0 whatever it found; `ok` holds the result.

```bash
gdd g2 cart-total --role builder-build
```

You should see:
