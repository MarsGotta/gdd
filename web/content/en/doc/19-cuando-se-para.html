When it stops

Each row is something you see, why it happens and what you do. Most of the time the answer is nothing: your agent goes on by itself and tells you in one line why it stopped. When it's your turn, it asks you one thing, with what it would do.

When installing

You seeWhyWhat you do
claude plugin list doesn't show gdd@gddThe plugin never got installed, or your Claude Code is older than 2.1.275.Update Claude Code to 2.1.275 or later and install it again with the command in Get started.
codex plugin list doesn't show gdd@gddOne of the two steps is missing: adding the source or installing from it.Run both again: codex plugin marketplace add MarsGotta/gdd and codex plugin add gdd@gdd.
agy plugin list doesn't show gdd, or shows an old versionIt was installed from inside the gdd folder, or the clone isn't up to date.Run git pull inside the gdd folder and, from the folder that holds it, agy plugin install gdd again.
It's on the list, but your agent doesn't know GDDA session that was already open doesn't load a new plugin.Close the session and open another.
Your agent says Rust is missingThe layer is built with Rust 1.89 or later.Install it and tell your agent: it picks up where it was.
Your agent says it has no network to build the layerThe first time, it downloads what it needs from crates.io.Give it network that once, or run the command it gives you in your terminal. It never downloads a ready-built layer from anywhere else.

In every case, check it with the list of plugins in a terminal, as in Get started, and then open a new session.

During a change

You seeWhyWhat you do
It waits for your approvalYour blueprint asks for a person there: the brief before anyone builds, or the pull request at the end.Read it and approve it. No agent can do that for you.
@assumed above a ruleYour agent chose that rule.Correct it if it isn't yours. When you approve, the tag stays.
@question above a ruleThe answer can wait for another change.Nothing for now: the question stays in sight in the file.
A check failsA fix round, with the command, its exit code and its last lines.Nothing, unless a limit runs out.
fix from the reviewerThe sealed tests it names get corrected first, and the builder takes the rest.Nothing.
stop from the reviewerThe change doesn't go in, whatever else the answer says.Read why.
The color roseThe change touched something more delicate than expected, and it goes back to Brief.Approve the new brief, if its color asks for it.
CANNOT: and a reasonA role stopped because the change doesn't fit as it was briefed.Nothing, unless what has to pass changes and its color asks for your approval.
The seal check failsSomething that judges the change was touched.The change stops, and your agent tells you.
A limit runs outThe change used up its attempts, its time or its cost. What's already built still gets judged.It tells you what works, what's missing and what one more attempt buys, and proposes a way out. .gdd/gdd limits <id> shows you how much of each limit it used.
A change is larger than expectedIt goes past the lines your blueprint gives as a notice, 400 in the template.Nothing: the reviewer knows, and it reaches you in one line.
A check fails without the change tooDebt that isn't in gdd/debt.md yet, or an unstable check. Meanwhile nothing gets built on top, because nothing would get through.It proposes a way out. Recording debt or quarantining a check is for you, or your team, to decide.
You need to skip a check, in an emergencySkipping it loosens it. Your blueprint says beforehand what may be skipped and who opens that gate.That person approves it. It goes in the log with who and why, and the change goes through what it skipped afterwards.
Your agent can't launch other agentsIt gives you, for each role, the model and the text to open it with.Open a new session for each role, with that model and that text.

Nothing gets fixed by loosening a check. When one looks wrong, only whoever wrote it or a person corrects it, never the agent that has to pass it.

With the layer

You seeWhyWhat you do
The layer refuses a stepA step out of order, a file that changed after it was sealed or a cap with no room left.Nothing: it says why and what to run instead, and your agent does that.
The layer sends the reviewer's report backA finding of its fix has no citation or, on red, no command that reproduces it.Nothing: your agent hands it back to the same reviewer, who completes it.
The layer refuses a brief over the form of a scenarioA new or changed scenario has no rule above it, no @id or more than one action.Nothing: your agent corrects it and seals again.
The layer isn't thereEvery copy of the project builds its own, and this one couldn't.Install Rust, and your agent goes on.
Your agent says git can't write in this copyGit won't let it write a branch in the folder it's in.Open it in a copy where git can write, and it goes on.
In your CI, the layer refuses everything, verify includedThe job runs in a container that checks the repository out as another user, and git refuses to read it.Add to the job, before the layer, git config --global --add safe.directory "$PWD".
gdd verify --all fails in your CIA log is broken, a hash doesn't match or a step came out of order.Hand your agent the line it names. A log isn't edited by hand: it gets corrected with a new event, which leaves in sight what was corrected.

Many of these answers come from the layer, and the commands that are useful to you are in The layer's commands.
