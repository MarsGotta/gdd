The skills

You've set up your first gate by hand and it works. The next change you'd like to leave entirely to your agents: one writes the scenarios with you, another builds the checks, a third does the work, and someone who has seen none of that reviews it. That's a lot to explain every time, so it's written down once, in seven skills.

A skill is a file of instructions your agent loads when it needs it. The GDD ones install nothing and carry no code: they use what your project already has, its tests, its linter, its CI and git. One is the entry skill, gdd, which hands out the work, and there are six more, one per role.

The seven

SkillWho loads itWhat it leaves
gddThe orchestrator. It loads by itself when you ask for a changeWhat comes next, and who gets launched.
gdd-prepareThe orchestrator, with youThe blueprint, with the gates your project needs, and the constitution.
gdd-briefThe orchestrator, on every changeWhat has to pass, as scenarios, and the expected risk.
gdd-checksAnother agent, never the one that buildsThe checks, each seen failing for the right reason.
gdd-buildThe agent that goes through the gateThe change, and the facts that prove it.
gdd-reviewThe reviewer, with a clean contextIts verdict, and the risk worked out again.
gdd-hardenThe orchestrator, with you, when something slips throughThe crack, and the check that would have caught it.

Whoever builds the checks, whoever builds the change and whoever reviews it each work in a separate agent, which starts without the others' conversation: it gets what they left written, not how they got there. That way the reviewer judges the change in front of it, without having heard how it was made (The pieces and the roles).

How to install them

You need a git repository and an agent that loads skills. On three of them, Claude Code, Codex and Antigravity, the seven come in at once, as a plugin with no code.

On Claude Code you type it inside the agent. It also brings three subagents, one for each role that works in an agent of its own.

On Codex it takes two steps in the terminal: you add the GDD repository as a source of plugins and install it from there.

On Antigravity you clone the repository and install the plugin from its folder.

If you'd rather keep them inside your project, copy the seven folders whose names start with gdd from the repository into .claude/skills/ on Claude Code or .agents/skills/ on Codex.

To find out whether they're in, each agent has its own command:

The first thing you ask for

With the skills in, ask your agent to set GDD up in your project. There's no command to remember, because gdd loads by itself. That first conversation is with you and needs your agent's deepest model: if you aren't on it, it tells you before it starts.

  1. It proposes the zones of your project and the gates it needs, and you correct what doesn't fit. It asks only what changes a zone or a gate: money, accounts and permissions, personal data, what can't be undone.
  2. It prepares the protections with you and tries them. It writes which files ask for your review, and what has to be applied on your platform you apply yourself. Then it tries four things from the environment the building agent will work in, pushing to the main branch among them. If any of them succeeds, your blueprint says so, and the agent not touching what judges it stays a rule.
  3. You approve the blueprint, or your team does if you work with one, with a commit or a pull request from a person, never from an agent.
  4. Another agent sets up the standing checks, once for the whole project, and a reviewer tries to fool them. No change starts until they are on the main branch.

From there you ask for each change in your own words, and you hear about it when it needs you and when it's in. Every step, with what you say, what happens and what you end up with, is in the repository's guide.

That same repository holds the tests the skills are checked with, run with a real model.

What they leave in your repository

Everything ends up in files you can read, in a gdd/ folder: the blueprint, the brief of each change with its scenarios and a log of what happened, with who approved what. Those files make sense without the skills. An engine will read and write the same ones, so what you set up today will still serve you later.

What they don't guarantee

What they don't give you is a guarantee. Without an engine, the agent not touching what judges it is a rule: the skills tell it so and then check that it hasn't, but nothing stops it. With protected branches and the permissions of your platform you get a good part of the way, and your blueprint says which of the three degrees you're at (How a gate gets fooled). Only an engine gives the full guarantee, and what's missing without one is in The engine.

With skills or by hand, what is delicate stays delicate. What changes when the thing you touch is payment, I tell in A delicate case.
