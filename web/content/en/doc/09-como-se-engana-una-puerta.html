How a gate gets fooled

A gate can be fooled without touching the test, and there are four ways to do it:

TrickExampleWhat stops it
LyingSays "everything passes" without running itSomeone else runs it
Faking the resultPrints 3 passed, or leaves a fake vitest in node_modulesSomeone else runs it, on a clean copy
Changing what surrounds the test"test": "exit 0" in package.json, or a hook in conftest.py that skips every testCompare those files with what was approved. CI alone is not enough, because it runs whatever is on the branch
Cheating from the codeif (name === "Ana") return "Hello, Ana", or if (process.env.VITEST)No tool prevents it: more cases, hidden scenarios or a reviewer that runs it

That hook in conftest.py has already happened: OpenAI saw a model add it, and ImpossibleBench classifies four cheating strategies, three of which don't modify the test.

Rule and guarantee

The fifth principle starts out as a rule, and a rule works without an engine: you ask the agent and review the diff. That works as long as you keep looking. The guarantee comes when the agent can't touch the check even if it tries. Protected branches and permissions get you a good part of the way (you set them up in Start today), but the full guarantee, where not even whoever administers the repository can loosen it without a person's approval, only an engine gives. The core is the list of those guarantees.

Is CI mandatory?

No. What's mandatory is that the agent doesn't judge itself. The test can be run by CI, by an engine or by you on a clean copy. CI is just the cheapest way not to depend on your discipline.

What really stops these tricks is the guarantees, so the question is which ones you can demand. The whole list is in The core.
